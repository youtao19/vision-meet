## 二、一句话定位

本产品是一套面向高校学生的 **「岗位理解 → 能力画像 → 人岗匹配 → 职业路径 → 生涯报告 → 导出归档」** 全链路 Web 应用：以企业提供的计算机类岗位大数据为基础，结合 **大语言模型与智能体编排（Pi Coding Agent）**、**向量检索（PostgreSQL + pgvector）** 与 **岗位路径图谱（Neo4j）**，帮助学生把碎片化自我认知与岗位要求对齐，输出 **可解释、可编辑、可导出** 的职业生涯发展材料。

---

## 三、行业背景与痛点（赛题对齐）

在数字经济与产业升级背景下，就业市场呈现「新兴领域缺人」与「部分专业就业难」并存的结构性矛盾。大学生职业规划困难，往往源于：

1. **自我认知模糊**：兴趣、能力、性格与岗位匹配关系不清，易跟风考研、考公或「进大厂」，规划缺少个性化与可行性。  
2. **职业信息不对称**：行业与岗位信息来源碎片化，对 AI、新能源等新兴岗位的真实技能与风险认知不足。  
3. **外部支持薄弱**：高校生涯课偏理论与技巧，一线产业洞察不足；家庭引导两极化。  
4. **规划难落地**：缺少实习与项目验证，面对行业快速变化缺少动态调整方法与评估指标。

**本产品价值**：在同一平台内完成 **岗位要求结构化拆解**、**个人能力结构化画像**、**多维度量化匹配与差距解释**、**结合图谱的发展路径展示** 以及 **分阶段行动计划与报告导出**，降低「从信息到行动」的摩擦成本。

## 五、核心能力清单（对照赛题 6. 任务要求）

### 5.1 就业岗位要求画像

- 构建 **不少于 10 个** 目标岗位的 **结构化画像**（规范角色聚合后可覆盖远多于 10 条原始导入岗位）。  
- 画像维度覆盖赛题要求方向，包括但不限于：**专业技能**、**证书要求**、**创新能力**、**学习能力**、**抗压能力**、**沟通能力**、**实习/项目能力** 等（以 `GET /api/v2/canonical-roles*`、`GET /api/v2/job-profiles` 等返回与契约为准）。  
- **数据侧**：`POST /api/v1/jobs/import` 导入原始岗位；可选 **`npm run data:pipeline:*` + `POST /api/v2/jobs/pipeline/run`** 触发归一化与智能流水线，再在前端 **「岗位画像」** 页浏览标准岗位画像。

### 5.2 岗位关联图谱与路径

- **垂直岗位图谱**：展示岗位描述及 **晋升路径** 关联（`promotion_routes`）。  
- **换岗路径图谱**：相关岗位 **血缘 / 转换** 关系（`transition_routes`）。  
- 赛题量化要求：**至少 5 个岗位** 具备换岗规划，**每个岗位不少于 2 条** 换岗路径（已在工程里程碑中落地，详见《项目详细方案》第三、四篇）。

### 5.3 学生就业能力画像

- 数据来源：**简历上传** 或 **表单自行录入**。  
- **简历解析**：`profile.resume-parser` 负责常见格式 **转纯文本**（如 `pdftotext` / `textutil` 等）；**图片类（png/jpg/webp 等）** 与 **PDF 文本抽取失败** 时走 **`profile.resume-vision`**（Pi Agent **多模态** 抽取姓名、目标岗与正文）；未启用视觉解析时图片上传返回 **`RESUME_VISION_UNAVAILABLE`**。  
- 输出：**结构化能力画像**、**完整度评分**、**竞争力评分** 及与赛题方向一致的维度刻画（业务抽取与评分规则在 `profile.service`，与「规则打分」边界见详细方案）。  
- 大模型：**视觉简历**与后续结构化字段推断受控在 **profile + Pi** 链路，避免与「四维规则评分」混为一谈。

### 5.4 学生职业生涯发展报告

- **职业探索与岗位匹配**：结合岗位画像与学生画像，输出 **契合度与差距** 的量化与文字解释。  
- **职业目标与路径规划**：报告内 **career_path** 章节与 **Neo4j 图谱 API** 联动，展示晋升与换岗路径。  
- **行动计划**：**短期 / 中期** 计划章节，含学习与实践安排建议；报告结构支持后续扩展「评估周期与指标」字段。  
- **编辑与导出**：支持 **手动编辑** 各章节并保存；**报告页已集成「AI 润色」**（调用 **`POST /api/v2/ai/polish`**，支持单章与全文顺序处理）；支持 **PDF 导出与下载**。

### 5.5 技术要求与指标（赛题）

- **大模型应用**：以 **Pi Coding Agent** 作为业务侧统一智能体编排入口（`/api/v1/agent/*`），并与 **RAG（qmd + pgvector）** 协同；另提供 **`/api/v2/ai/*` AI 中枢**（任务、对话、**文本润色**、简历 HTML 生成等），与 Pi 工具链对齐，避免并行维护独立「裸 Chat Completions」业务主链路。岗位画像主数据由 **`jobs-intelligence`** 从归一化事实与规范角色聚合，规则/统计基线为主，可按迭代接入更强生成能力。  
- **可操作性、可解释性**：匹配结果包含 **四维得分、加权总分、差距列表、改进建议与解释字段**；可选 **`/api/v2/matches*`、`/api/v2/reports*`** 获得含路径建议、证据引用等增强字段（与 V1 并存）。  
- **准确性**：依据仓库内 **30 条手工抽样** 评测（20 条匹配 + 10 条画像），**人岗匹配关键技能匹配准确率 80%**、**画像关键信息准确率 92%**，综合判定 **达到赛题阈值**（≥80% / >90%）。数据来源：`data/evaluation/match.manual-samples.jsonl`、`data/evaluation/profile.manual-samples.jsonl`，复算命令见《项目详细方案》第九篇；归一化与图谱质量可辅以 **`npm run evaluation:normalized:e2e`**、图谱 E2E 脚本（见《项目详细方案》第九篇 §9.2 与 `data/evaluation/`）。  
- **实用性**：Vue 3 前端（**统一 `AppLayout` 导航**、首页、数据流水线、岗位画像、学生画像、匹配、报告、职业路径等）与 REST API 联调；**独立 Agent 演示页已下线**，智能体能力通过 **Agent API、报告内润色与 AI 接口** 使用。

## 六、技术架构亮点（摘要）

- **单仓 Monorepo**：`apps/frontend`（Vue 3 + TypeScript + Vite + Pinia + Vue Router）、`apps/backend`（Node.js + Express + TypeScript + Zod）、`packages/contracts`（OpenAPI + 共享类型），**契约优先** 协作。  
- **数据层**：**PostgreSQL** 承载岗位原始记录、规范岗位事实、学生、匹配、报告与导出等；**pgvector** 承载知识库向量与混合检索；**Neo4j** 承载 **首轮种子图谱** 与 **V2 自动构建的岗位发展图谱**（`jobs-intelligence` 写入/查询）。  
- **业务域扩展**：**`jobs-intelligence`**（`/api/v2`：流水线、规范角色、岗位事实、V2 职业路径、兼容 `job-profiles` 列表）；**`ai`**（`/api/v2/ai`：任务、润色、简历 HTML 等）；**`profile`** 集成 **简历文本解析 + 多模态视觉解析**（`profile.resume-parser` / `profile.resume-vision`），并可注入 **`jobsRepository`** 辅助目标岗位与岗位库联动。  
- **智能层**：**Pi Coding Agent** 统一编排（Agent 与 AI 模块共享工具语义）；**qmd** 文档结构化切分 + 索引脚本（`knowledge:index:*`、`knowledge:baseline`）支撑本地知识库建设（对应企业要求提交的「本地知识库资料」）。  
- **工程质量**：统一 **Node 22.20+**（见根目录 `.nvmrc` / `package.json` engines）；`npm run type-check` 作为合入基线；接口 **`/api/v1` 主链路** 与 **`/api/v2` 增强链路** 并存。

## 七、创新点（评委视角）

1. **可解释的人岗匹配**：严格按赛题四维框架打分，并输出 **可追踪的说明与改进建议**，而非单一「匹配度百分比」。  
2. **路径图谱与报告联动**：图谱查询接口与报告 **career_path** 章节同一数据源逻辑，避免「报告与图谱各说各话」。  
3. **结构化报告 + 版本化**：同一匹配结果可生成多版报告，便于迭代对比与答辩展示。  
4. **可演进架构**：Repository 适配器模式，关系库 / 向量 / 图谱分层清晰；**岗位智能（PG + Neo4j）** 与 **AI 中枢** 分域挂载，便于从演示环境扩展到院校私有化部署。
