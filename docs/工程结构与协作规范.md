# 工程结构与协作规范

更新时间：2026-04-01

## 1. 目标

建立可协同的 monorepo 开发模式，确保前后端与契约同步演进，避免结构漂移与跨层耦合。

## 2. Monorepo 约束

1. 仓库根使用 `npm workspaces` 管理 `apps/*` 与 `packages/*`。
2. 统一从根目录执行开发命令：`npm run dev`、`npm run type-check`、`npm run build`。
3. 统一格式化命令：`npm run format`，校验命令：`npm run format:check`。
4. 新增 workspace 必须加入根 `package.json` 的 `workspaces` 声明。

## 3. 前端结构规范

固定目录：

- `apps/frontend/src/app`：应用装配层（入口、路由、provider）。
- `apps/frontend/src/features/<feature>`：业务功能层（pages/components/stores/routes）。
- `apps/frontend/src/shared`：共享层（api/ui/utils）。

强制规则：

1. 禁止在 `src/` 根目录新增业务逻辑文件。
2. feature 间禁止直接耦合，跨 feature 复用必须下沉到 `shared`。
3. 路由聚合在 `app/router`，feature 自身只导出路由片段。

## 4. 后端结构规范

固定目录：

- `apps/backend/src/modules/<domain>`：领域模块。
- `apps/backend/src/shared`：跨领域公共能力（配置、中间件、日志等）。

每个领域模块至少包含：

- `*.route.ts`
- `*.schemas.ts`
- `*.service.ts`
- `*.repository.ts`
- `*.repository.<adapter>.ts`（如 `json`、`pg`）

强制规则：

1. `route` 只做协议转换和参数校验，不得直接读写数据源。
2. `service` 组织业务流程，不依赖具体存储实现。
3. 数据源切换仅修改 repository adapter，不修改业务流程。

## 5. 契约优先规范

1. OpenAPI 文件统一放在 `packages/contracts/openapi/`。
2. 共享类型统一放在 `packages/contracts/types/`。
3. 前后端接口字段变更流程：

- 先更新 contracts；
- 再更新后端实现；
- 最后更新前端消费。

## 6. 配置与环境规范

1. 每个应用必须维护 `.env.example`。
2. 配置读取必须集中在配置模块，并进行启动时校验（zod）。
3. 禁止在脚本中写绝对路径，统一使用相对路径推导根目录。

## 7. 质量门槛

当前最低门槛：

1. `npm run type-check` 必须通过。
2. 应用本地启动可运行。

建议逐步补齐：

1. `eslint + prettier`。
2. `vitest + supertest`。
3. CI 执行 `type-check + unit`。
