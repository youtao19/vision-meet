# 问题记录规范

## 1. 目的

将每次已解决问题沉淀为可检索、可复用经验，避免重复踩坑。

## 2. 存储位置

1. 结构化记录文件：`docs/问题记录库.jsonl`
2. 一行一条 JSON，便于 `rg`、脚本、数据库导入。

## 3. 字段规范

1. `id`：唯一编号，建议 `ISSUE-YYYYMMDD-序号`。
2. `occurred_at`：问题出现或确认时间（ISO 8601）。
3. `resolved_at`：问题解决时间（ISO 8601）。
4. `module`：问题所属模块（如 `apps/backend`）。
5. `symptom`：问题现象。
6. `root_cause`：原因分析。
7. `resolution_steps`：解决步骤（字符串数组）。
8. `conclusion`：最终结论。
9. `tags`：可检索标签（字符串数组）。
10. `status`：固定为 `resolved`（已解决问题入库）。

## 4. 记录时机

1. 每次问题确认“已解决”后立即记录。
2. 代码变更与文档变更在同一批次提交。

## 5. 检索示例

```bash
rg "python command not found" docs/问题记录库.jsonl
rg "\"module\":\"apps/backend\"" docs/问题记录库.jsonl
rg "\"tags\":\\[.*uv.*\\]" docs/问题记录库.jsonl
```
