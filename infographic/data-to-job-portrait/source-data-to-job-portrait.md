# 数据处理到岗位画像生成

## 页面目标

作为“总体技术架构”中“数据处理 / 岗位画像”模块的详细说明页，解释该功能使用了什么技术，以及从原始岗位数据到标准岗位画像的具体实现方式。

## 功能定位

数据处理中心是系统的数据生产入口。它负责把原始岗位数据转换成可用于岗位画像、学生匹配、路径图谱和职业报告的结构化岗位资产。

## 用到的技术

1. Vue3 + TypeScript
   - 用于前端数据处理中心页面展示。
   - 展示任务启动按钮、阶段时间线、进度条、当前生成岗位、生成数量。

2. Fetch API + OpenAPI / Contracts
   - 前端通过统一接口契约调用后端。
   - 任务启动接口：POST /api/v2/jobs/pipeline/run。
   - 任务查询接口：GET /api/v2/jobs/pipeline/tasks/{task_id}。

3. Express + TypeScript + Zod
   - Express 承载后端 API 路由。
   - Zod 校验任务启动参数和任务查询参数。
   - Route 层只负责协议转换，业务逻辑进入 service。

4. JobsIntelligenceService
   - 编排完整流水线。
   - 创建任务、读取岗位、清洗归一、调用 Agent、写入结果、更新任务状态。

5. PostgreSQL Repository Adapter
   - 存储原始岗位数据、清洗后岗位数据、Agent 生成的岗位画像、任务状态。
   - 通过 repository adapter 解耦存储实现，方便未来替换或扩展。

6. Pi Agent
   - 基于清洗后的岗位统计摘要生成 10 条岗位画像。
   - 画像字段包括岗位名称、分类、技能、证书、创新、学习、抗压、沟通、经验等维度。

7. 任务流水线 + 失败重试
   - 任务状态包括 running、success、failed。
   - 失败任务进入记录与重试队列，支持 claim -> processing -> done / failed / pending 的闭环流转。

## 具体实现流程

1. 用户点击“开始生成画像”。
2. 前端创建或展示任务，页面进入运行态。
3. 后端创建 pipeline task，返回任务 ID。
4. service 读取岗位数据。
5. 对岗位标题、岗位族、地点、薪资、公司、行业、描述文本进行清洗归一。
6. 提取关键词，形成 cleaned_jobs。
7. 将全量岗位数据压缩为统计摘要，避免把 1W 明细直接输入 Agent。
8. 调用 Pi Agent，要求只返回岗位画像 JSON 数组。
9. 校验 Agent 输出数量和字段结构。
10. 将岗位画像写入 agent_job_portraits 和 manual_job_portraits。
11. 更新任务进度、生成数量、完成状态。
12. 岗位画像中心读取结果并展示列表和漫画化岗位画像。

## 页面建议表达

标题：数据处理到岗位画像生成

副标题：从原始岗位表到可展示、可匹配、可复用的标准岗位资产

核心流程：原始岗位数据 → 清洗归一 → 统计摘要 → Pi Agent 生成 → 画像入库 → 漫画化展示

底部总结：该模块不是简单导入数据，而是通过“任务流水线 + Agent 生成 + 结构化入库”把岗位数据沉淀为系统后续匹配、图谱和报告的基础资产。
